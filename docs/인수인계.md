## 0. 먼저 알아야 할 것 — 이 문서는 2판이다

초판은 "하네스 하나짜리 문서 + 파란 블록 캔버스" 기준이었다.
그 뒤 Claude Design 리디자인을 적용하면서 **캔버스를 통째로 다시 짓고,
문서 구조를 세트(하네스 여러 종)로 올렸다.** 초판을 기억하고 있다면 아래가 다르다.

| 항목 | 초판 | 지금 |
|---|---|---|
| 문서 | 하네스 하나 (`schemaVersion 1`) | **세트** (`KitDocument`, `schemaVersion 2`) |
| 캔버스 | 파란 라운드 박스 + 베지어 곡선 | **도면형** — 하우징 심볼 + 직교 라우팅 |
| 스타일 | `App.css` 210줄에 하드코딩 | `tokens.css` CSS 변수 + 화면별 CSS 분리 |
| PDF | 화면 스냅샷(`html-to-image`) | **벡터로 직접 그림** |
| 파일 수 | 20개 남짓 | 70개 (소스 45 + 테스트 25) |

**⚠️ 아직 실제 브라우저에서 손으로 검증되지 않았다.** 같은 폴더의
`검증-체크리스트.md` 를 먼저 돌려보고 시작할 것. 특히 **PDF 는 아무도 열어본 적이 없다.**

## 2. 이 툴이 무엇인가

하네스 제작 시 **하우징 선택 → 핀별 선 색 → 상대 커넥터 연결 → 배선도 작성**이
매번 막막한 문제를 해결하는 사내 웹 툴.

핵심 산출물은 **PDF 배선도 + 접속표(From-To) + 파트리스트**.

- 백엔드 없음 (브라우저에서 전부 처리, JSON 파일로 저장/불러오기)
- React 18 + TypeScript + React Flow(@xyflow/react) + Zustand
- 의존성은 5개뿐: `@xyflow/react` `jspdf` `react` `react-dom` `zustand`
- GitHub Pages 정적 배포

## 3. 설계에서 반드시 알아야 할 것

### 3-1. 문서는 2층이다 — 세트 / 하네스

**자판기 1대분 = 하네스 A 1개 + B 2개 + C 1개** 처럼, 발주 단위는
하네스 하나가 아니라 **그것들을 묶은 세트**다.

```ts
KitDocument {            // 최상위 저장 단위 (schemaVersion 2)
  harnesses: HarnessDocument[]   // 하네스 여러 종
  set: HarnessSet                // 품번, 세트당 수량, 주문 세트 수
}
```

핵심 설계 판단: **`HarnessDocument` 는 "하네스 한 종"으로 그대로 뒀다.**
캔버스·접속표·속성·핀맵·검증은 전부 하네스 하나만 다루므로,
세트를 위에 감싸는 방식으로 올리면 기존 코드가 손대지 않고 그대로 돈다.

스토어도 같은 원리다. `doc` = 활성 하네스이고, 기존 액션 15개는 전부 `doc` 만
건드린다. 구독 하나가 `doc` 변경을 `kit` 에 되돌려 쓴다(`harnessStore.ts` 하단).
**새 기능을 만들 때도 되도록 이 규칙을 지켜라** — `doc` 만 보면 되는 화면은
`kit` 을 몰라도 된다.

> **총수량은 절대 저장하지 않는다.** 언제나 `perSet × orderQty` 로 파생한다
> (`store/kit.ts`). 수동 입력 총수량을 두는 순간 화면 숫자와 발주 숫자가
> 갈라지고, 그때부터 아무도 화면을 믿지 않는다.

`schemaVersion 1` 파일은 열 때 자동 마이그레이션된다(`toKit()`).
저장 키를 `harness-tool:doc:v1` / `harness-tool:kit:v2` 로 분리해 뒀다 —
구버전 앱이 열려 있어도 v2 를 덮어쓰지 않는다.

### 3-2. 타입 계약이 중심 (`src/types/index.ts`)

이 파일이 **동결된 계약**이다. 변경 시 `schemaVersion` 과 마이그레이션을 함께 고려하라.
`drawingNo` `rev` `letter` 처럼 **optional 필드 추가는 하위호환**이므로 버전을 올리지 않았다.

### 3-3. 스플라이스를 특수 케이스로 만들지 않았다

Y자 분기·한 핀 다중 결선이 이 툴의 가장 까다로운 지점이었다. 해법:

- **모든 연결점을 "커넥터"로 통일**한다 (일반/보드투와이어/스플라이스 전부 같은 구조)
- 스플라이스 = `Connector.bridges` 에 "내부적으로 이어진 핀 그룹"을 담은 커넥터
- Y자 분기 = 여러 와이어가 같은 스플라이스를 공유 → 자연히 한 네트
- 한 핀 다중 결선 = 여러 와이어가 같은 `PinRef` 를 공유 → 자연히 합쳐짐

### 3-4. 넷리스트 엔진 (`src/store/netlist.ts`)

union-find 로 **와이어 + 스플라이스 브리지**를 합쳐 전기적으로 이어진 네트를 계산한다.
접속표의 NET 열, 캔버스 하이라이트, 검증의 게이지 불일치가 전부 여기서 나온다.
**이게 이 툴의 심장이다.** 배선 관련 기능을 추가할 땐 여기부터 확인.

### 3-5. 파생 vs 저장 — 세 번 같은 판단을 했다

| 대상 | 판단 | 이유 |
|---|---|---|
| 총수량 | 파생 | 저장하면 화면과 발주가 갈라진다 |
| 배선 레인(y 오프셋) | 파생 | 도면을 고치면 레인도 따라와야 한다 |
| 물리 뷰 구간(Segment) | 파생 | 저장하면 도면과 구간이 갈라진다 |

Claude Design README 는 구간을 저장 스키마(`Seg`)로 제안했지만 따르지 않았다.
**"화면에서 계산할 수 있는 것은 저장하지 않는다"** 가 이 코드베이스의 규칙이다.

### 3-6. 문서 자기완결성

`HarnessDocument.usedParts` 에 사용한 부품 스냅샷이 함께 저장된다.
→ JSON 파일 하나만 넘겨도 상대방 쪽에서 도면이 그대로 재현된다.
검증 규칙 `housing-missing` 이 이 성질이 깨졌는지 감시한다.

## 5. 디자인 규칙 (어기면 리디자인이 무너진다)

`src/tokens.css` 가 단일 출처다. **하드코딩 hex 금지.**

1. **UI 강조색은 스틸 `--accent`(#5980a6) 하나.**
2. **빨강은 UI 에서 쓰지 않는다.** 빨강은 전선 색이다. 캔버스에 빨간 배선이
   그대로 그려지므로 UI 가 빨강을 쓰면 구분이 안 된다.
   예외는 삭제 버튼(`--danger`) 하나뿐이다.
3. **밀도 우선.** 컨트롤 26px(보조 22–24px), 본문 12.5px, 표 12px, 최소 10px.
   여백을 늘려 스크롤이 길어지는 "개선"은 이 툴에선 개악이다.
4. **도면 요소는 radius 0**, 컨트롤만 2px.
5. **한글 라벨 기준으로 폭을 잡는다.** 영문보다 길다.
6. **정밀 도면에 트랜지션을 넣지 않는다.** 강조 전환은 즉시.
7. 숫자·식별자는 `--font-num`(Barlow) + `tabular-nums`. 폰트를 못 받아도
   자릿수 정렬은 유지된다(사내망에서 Google Fonts 가 막힐 수 있다).

## 6. 구현 완료 목록

**캔버스 (도면형)**
- 하우징 심볼: 핀 패드 26px/30px 피치 격자, 래치 돌기(결합 방향), 좌상단 등록 마크,
  레퍼런스 라벨(J1/SP1/D1), MPN 캡션
- 직교(맨해튼) 라우팅 + **구간 겹침 채색**으로 레인 자동 배정
- 스텁 라벨(색 약호 + 신호명), 도면 프레임 + 제목블록(도번·SCALE·Rev)
- 캔버스 ↔ 접속표 **양방향 hover 동기 강조** + 커서 옆 상세 카드
- 선택 모델 3단계: 호버(임시) / 클릭(고정) / Shift·박스 드래그(다중), ESC 한 단계씩
- 라이브러리에서 **드래그해 원하는 자리에 배치**
- 팬: 스페이스+드래그, 두 손가락 스크롤, 가운데/오른쪽 버튼. 줌은 ⌘+스크롤

**세트**
- 하네스 탭 스트립 + 세트 개요(하네스 카드 · 미니 스케마틱 · 세트당 수량)
- 세트 패널: 주문 세트 수, 세트 구성, **발주 전 확인**
- 파트 탭: 파트 단위 / 하네스 단위, 집계 범위(하네스별·세트 전체), 발주 문구 생성

**편집**
- 속성 4상태(와이어·커넥터·장치·미선택) + 다중 선택 공통 편집
- 색: 규격 12색 칩 + 자유 입력 병행
- 커넥터 방향: 하우징 심볼 4카드
- **터미널 지정: 핀 패드 격자에서 다중 선택 → 일괄 지정** (핀이 24개여도 컨트롤은 2개)
- 실행취소 50단계 + 파괴적 동작에 토스트(확인 대화상자 없음)

**핀맵 에디터**
- 2열 구성, 핀 속성 가로 스트립 상주
- 1번 핀 위치 4택 × 핀 번호 방향 3택 조합
- 캔버스와 동일한 하우징 심볼로 그려 "정의한 그대로 도면에 나온다"

**물리 뷰 (제조 도면)**
- 구간 자동 산출(배선 그래프 → 최대 신장 숲 → 분기점 삽입)
- 다발 굵기 = 본수, 분기점 마커, 치수선, 구간표 + 자재 요약

**검증** — 11개 규칙, 각 지적에 **왜 문제인지** 한 문장
`pin-overflow` `pin-multi-wire` `terminal-missing` `length-missing` `floating`
`splice-underused` `std-color-mismatch` `self-loop` `duplicate-wire`
`gauge-mismatch` `housing-missing`

**출력**
- PDF: 벡터로 직접 그림. 하네스당 3면(배선도·접속표·파트리스트), 세트 묶음 지원
- 접속표 CSV, 파트리스트 CSV
- 부품 라이브러리 JSON/CSV 가져오기 (한글·영문 헤더, 잘못된 행만 건너뜀)

## 7. 알려진 한계 / 다음 후보

### ⚠️ 검증 안 된 부분 — 가장 중요

**실제 브라우저에서 손으로 확인된 것이 거의 없다.** 자동화 테스트 341개와
스크린샷으로만 검증했다. 특히:

- **PDF 를 아무도 열어본 적이 없다.** 핵심 산출물인데. 한글이 Canvas 래스터로
  들어가는데 인쇄에서 어떻게 나오는지 미확인
- 드래그 결선, 드래그 배치 — HTML5 DnD 는 jsdom 으로 판정 불가
- 배선 20가닥 이상에서 레인 채색이 실제로 안 겹치는지
- 물리 뷰 구간 산출이 분기가 여럿인 실제 하네스에서 맞는지
- 부품 CSV 를 실제 엑셀 부품표로 넣어본 적 없음

→ `검증-체크리스트.md` 를 먼저 돌려라.

### 미구현
- 하네스 **요소 단위** 복제·이동 (하네스 통째 복제는 세트 개요에 있음)
- 커넥터 암수 짝 관리
- 핀맵 에디터의 비정형 배치(핀을 그리드 밖 임의 위치로)
- 레인 **수동 조정**(드래그로 옮겨 `laneOverride` 고정) — 자동 배정만 있음
- 보호재(슬리브·테이프) 데이터 모델 — 물리 뷰 구간표에 `미지정` 으로 비어 있음
- 전장(全長) 정확 계산 — 구간 데이터가 없어 근사치로 표시 중

### 개선 후보
- 실측 길이 기반 케이블 재단 리스트
- 커스텀 라이브러리 부품 더 채우기 (현재 시드 31종)
- 1280px 미만 화면 대응 (현재 1440×900 고정 전제)

## 8. 작업 히스토리에서 배운 것 (반복 방지)

실제로 겪은 문제들. 비슷한 작업 시 주의.

### 8-1. 환경

1. **이 Mac 셸에는 `NODE_ENV=production` 이 상시 설정돼 있다.**
   `npm ci` 가 devDependencies 를 통째로 건너뛰어 `tsc: command not found` 가 난다.
   → **`npm ci --include=dev`** 를 써라.
   같은 이유로 vite 가 React 프로덕션 빌드를 물어와 testing-library 의 `act()` 가
   전부 실패했다. `vitest.config.ts` 가 `NODE_ENV='test'` 로 고정해 막고 있다.
2. **CI 는 Node 22 여야 한다.** Node 20 에서 jsdom → undici 가
   `webidl.util.markAsUncloneable is not a function` 로 죽어 DOM 테스트가 로드조차 안 된다.

### 8-2. 캔버스 (React Flow)

3. **핸들은 핀 셀이 아니라 노드 가장자리에 절대 위치로 둔다.**
   셀에 붙이면 배선이 도형 중간에서 시작하는 것처럼 보인다.
4. **각 핀에 source/target 핸들이 모두 있어야 한다.**
   source 만 있으면 엣지가 노드 중심으로 폴백해 선이 엉뚱한 데서 나온다.
5. **핀 배치 축과 핸들 방향은 반드시 함께 바꾼다.**
   핀은 세로로 쌓여 있는데 핸들만 위로 옮기면 선이 옆구리에서 나온다.
6. **배선이 나가는 변에 글자를 두지 않는다.** 선이 글자를 뚫고 지나간다.
   레퍼런스 라벨·MPN 캡션에 **흰 배경 inline-block** 을 깐 것도 같은 이유다.
7. **React Flow 의 엣지 레이어는 zIndex 속성으로 안 눌린다.** CSS 로 눌러야 한다.
   (`.react-flow__edges { z-index: 0 !important; }`)
8. **`selectionOnDrag` 와 `panOnDrag` 는 짝으로만 동작한다.**
   박스 선택을 켜면 좌클릭 팬을 잃으므로 대체 수단(스페이스·스크롤)을 반드시 함께 열어라.
9. **`file://` 에서 localStorage 는 SecurityError 를 던진다.**
   try/catch 로 감싸지 않으면 앱이 통째로 죽는다 (`safeStorage()` 참고).

### 8-3. 판단

10. **UI 가 말하는 것과 실제로 되는 것이 어긋나면 그게 최악의 버그다.**
    실제로 두 번 냈다 — 빈 상태가 "캔버스에 끌어다 놓으라"면서 드롭을 못 받았고,
    "도번을 정해 두면 제목블록에 반영된다"면서 도번 입력란이 없었다.
    **안내 문구를 쓸 때마다 그게 실제로 되는지 확인하라.**
11. **없는 숫자를 지어내지 마라.** 길이·보호재·전장이 없으면 `—` 로 두고
    추정치는 추정임을 밝혀라. 도면은 발주로 이어지는 문서다.
12. **각 경고에 왜 문제인지 한 문장을 붙여라.** "규칙 위반"만 적으면 고칠 수가 없다.
13. **외부에서 참조할 수 있는 출력 형식은 함부로 바꾸지 마라.**
    접속표 CSV 헤더에 열을 추가하려다 되돌렸다 — 엑셀 매크로가 물려 있을 수 있다.
